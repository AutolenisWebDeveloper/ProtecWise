# ProtecWise Frontend Design Skill

## The Design Identity

ProtecWise is a life insurance brokerage. The subject is protection — families,
futures, the moment someone decides to stop putting this off. The audience is
25–55 year olds who are probably researching this for the first time and feel
some combination of overwhelmed, guilty about not having done it sooner, and
hopeful that it's easier than they think.

The single job of this design: make life insurance feel approachable, precise,
and trustworthy — in that order. Not corporate. Not clinical. Not cheerful in a
way that feels dishonest about the stakes.

## Signature Element

The shield from the ProtecWise logo is the design motif. It appears:
- As the logo in every header
- As a subtle background element on the homepage hero
- As the favicon and loading indicator
- As a visual metaphor in illustrations (a hand holding something, a curve
  that wraps around content)

The two-tone wordmark ("Protec" in navy + "Wise" in green) is the identity.
When referencing the brand in copy, mirror this: authority (navy concepts)
paired with wisdom/growth (green concepts).

**One aesthetic risk**: premium number treatment. Every premium amount, coverage
figure, and financial number uses JetBrains Mono with the decimal/cents in
65% opacity. This creates a distinctive "financial precision" feel that makes
ProtecWise read as serious, not amateur. Example:

```
$47.23/mo  →  <span class="premium-whole">47</span>
               <span class="premium-decimal">.23</span>
               <span class="premium-period">/mo</span>
```

## Color Rules

```
Primary:       #1B3D8B  — headings, nav, sidebar, primary buttons, trust elements
Accent:        #4AAE2E  — CTAs, Best Value badge, success states, Apply buttons
Secondary:     #4A9ED6  — info states, secondary links, step indicators
Navy tint:     #E8EEF9  — card backgrounds, badge fills, form section bg
Green tint:    #EBF6E5  — success badges, approved states, Best Value bg
Blue tint:     #EDF5FC  — info banners, secondary badge fills
Text:          #1A202C  — primary body
Muted:         #4A5568  — supporting text
Hint:          #718096  — labels, captions
Border:        #E2E8F0  — default
Surface:       #F8FAFC  — page background
White:         #FFFFFF  — cards, modals
```

Never use generic blue (#3B82F6) or teal (#16C79A) — those are not ProtecWise.
Never use a warm cream or terracotta palette — that reads as AI default.
Never use near-black backgrounds — ProtecWise is professional, not dark mode first.

## Typography Rules

```css
/* Display — hero headlines only */
.text-display {
  font-size: clamp(40px, 6vw, 64px);
  font-weight: 700;
  line-height: 1.05;
  color: #1B3D8B;
  letter-spacing: -1.5px;
}

/* H1 — page titles */
.text-h1 { font-size: clamp(28px, 4vw, 48px); font-weight: 700; color: #1B3D8B; }

/* H2 — section headings */
.text-h2 { font-size: clamp(22px, 3vw, 32px); font-weight: 700; color: #1B3D8B; }

/* H3 — card headings, subsections */
.text-h3 { font-size: 20px; font-weight: 600; color: #1B3D8B; }

/* Body */
.text-body { font-size: 16px; font-weight: 400; line-height: 1.7; color: #1A202C; }

/* Premium/financial numbers */
.text-premium {
  font-family: 'JetBrains Mono', monospace;
  font-size: 36px;
  font-weight: 700;
  color: #1B3D8B;
  letter-spacing: -1px;
}
.text-premium-decimal { opacity: 0.65; font-size: 0.65em; }

/* Carrier name, product name */
.text-carrier { font-size: 15px; font-weight: 600; color: #1A202C; }
.text-product  { font-size: 13px; font-weight: 400; color: #718096; }
```

**Never** use a serif font. ProtecWise is Inter (sans) + JetBrains Mono (numbers) only.
**Never** use font-weight 300 — it reads weak for a protection brand.
**Always** use letter-spacing: -1.5px on large headlines — it prevents the
loose-gap default that makes headlines look autogenerated.

## Layout Principles

### The hero is a thesis
Don't open any section with "We make insurance easy." Open with the real thing:
a statistic, a human moment, or the brand's own words. The ProtecWise hero is:

```
"Protecting What"   ← navy, large, weighted
"Matters Most"      ← green (#4AAE2E), slightly larger, bold
```

This echoes the logo tagline. The design enforces the brand, not describes it.

### Structure encodes meaning
Use numbered sections (01 / 02 / 03) ONLY for actual sequences:
the "How It Works" process steps, the application 8-step progress bar,
the onboarding 7-step flow. Never number feature lists or product types.

### Forms feel like conversations
Application intake steps show ONE thing at a time. No wall of fields.
Progress bar at top, single question in focus, secondary fields fade in
conditionally. The user should feel guided, not interrogated.

### Trust is woven in, not bolted on
Carrier logos appear in-context near quote results, not in a separate
"Our Partners" marquee. License information is in the footer, not on a
dedicated compliance page. Social proof (testimonials) appears after the
product explanation, not at the top where it feels desperate.


Button text: always sentence case. Never ALL CAPS. Never Title Case.

### Forms and Inputs
```
Input:        border:1px solid #E2E8F0  border-radius:8px  padding:10px 14px
Input focus:  border-color:#1B3D8B  box-shadow:0 0 0 3px #E8EEF9
Input error:  border-color:#C53030  box-shadow:0 0 0 3px #FDECEC
Label:        13px/500  color:#4A5568  margin-bottom:6px
Helper text:  12px/400  color:#718096
Error text:   12px/500  color:#C53030
```
Never use browser `alert()`. All errors are inline below the field.
Error messages: describe what happened + how to fix it. "Please enter a valid email"
is wrong. "Enter an email address like name@example.com" is right.

## Motion Rules

Motion should serve the subject (protection, security, stability).

**Use:**
- Step progress transitions: 200ms ease-out slide between application steps
- Number count-up: premium amounts count up from 0 on quote results page load
- Shield pulse: subtle scale(1.02) → scale(1) on logo hover (protective heartbeat)
- Toast slide: slide in from right, 300ms ease-out
- Page transitions: 150ms fade-out → 150ms fade-in on route change

**Don't use:**
- Parallax scrolling — reads as template
- Bounce animations — not appropriate for financial services
- Skeleton loaders that pulse — use solid gray placeholders instead
- Entrance animations on every element — pick maximum 2 animated elements per page

Respect `prefers-reduced-motion`. Wrap all animations:
```css
@media (prefers-reduced-motion: reduce) {
  * { animation-duration: 0.01ms !important; transition-duration: 0.01ms !important; }
}
```

## Copy Standards

These apply to every piece of text on the platform.

**Voice:** Intelligent, warm, direct. A trusted advisor, not an insurance salesman.

**Do:**
- "Get a quote" not "Request a quotation"
- "Your application is saved" not "Application data has been persisted"
- "We need your Social Security Number (last 4 digits only)" not "Enter SSN"
- "Protecting What Matters Most" not "Comprehensive Life Insurance Solutions"

**Don't:**
- Never "seamless" or "leverage" or "empower" — generic filler
- Never "successfully" in confirmations — the success state IS the confirmation
- Never "!" in system messages — reads anxious
- Never passive voice in error messages — "Something went wrong" → "We couldn't
  save your progress. Try again."
- Never "click here" — links name their destination

**Empty states are invitations:**
- No quotes: "Start your first quote in 60 seconds →"
- No leads: "Your leads will appear here once clients start quoting"
- No tasks: "No tasks today — your pipeline is clear"

## Responsive Standards

Public pages and client portal: mobile-first at 375px.
Agent and admin portals: desktop-first at 1280px, functional at 768px.
Recruiting site: mobile-first at 375px.

Test at exactly: 375px · 768px · 1280px · 1920px.
Never set fixed widths without a max-width. Use clamp() for fluid typography.
Touch targets minimum 44×44px on all interactive elements.

## Self-Critique Checklist

Before finishing any UI component or page, check:
- [ ] Does it use brand colors? (#1B3D8B, #4AAE2E, #4A9ED6 — not generic blue/green)
- [ ] Are financial numbers in JetBrains Mono?
- [ ] Does button text start with a verb, sentence case?
- [ ] Are error messages inline, not alerts?
- [ ] Does it work at 375px?
- [ ] Is the copy direct and specific, not generic?
- [ ] Does it have a loading state, empty state, and error state?
- [ ] Is the logo at /public/protecwiselogo.jpg with proper alt text?
- [ ] Do animated elements respect prefers-reduced-motion?
